# M1 可公開試玩版（教師優先）設計

- 日期：2026-10-12
- 狀態：使用者於 2026-10-12 同意第 2 節全部建議；程式部分已實作（2026-10-12），待部署設定與教師驗收（第 4 節）
- 範圍：讓專案從「開發者自己能跑」變成「一位老師拿到網址，就能生成世界、檢查內容、發給全班，學生用手機打開就能玩」。
- 框架依據：`framework/expert-quest-framework.md` v1.0（以下「框架 x.y」指其章節），主要是 4.2 P0、7.4、第 9 章第 12、14 條、第 12 章。

## 1. 目標使用者與核心流程

第一個目標使用者是**老師（課程設計者）**，學生是第二個使用者。

```
老師：教學頁 → 用聊天型 AI 生成世界 → 工作台匯入、修正
     → 審閱頁逐題檢查（標記錯題 → 併入修正請求）
     → 匯出「班級版」世界檔（依授權自動篩選）→ 發給學生（檔案或連結）
學生：打開網址 → 匯入班級版 → 直接進入遊戲（手機可玩、可離線）
```

和現有設計的差異：框架 7.4 預設「文件是玩家自己的，遊戲供個人學習使用」，第 2 節第 24 條把分享版列為「之後」。老師情境的核心就是「生成者≠使用者」，所以分享必須提前，也必須處理授權。

### 1.1 三種教材來源與能分享的程度

| 教材 | `source.license` | 能發給學生的內容 |
|---|---|---|
| 老師自編講義（老師是作者） | 老師選的授權（例如 `CC-BY-4.0`，或 `LicenseRef-Classroom` 僅限班級使用） | 全部 |
| 開放教材（OpenStax、LibreTexts 等） | 其授權（例如 `CC-BY-4.0`） | 全部，附出處 |
| 一般原文書（著作權保留） | `LicenseRef-All-Rights-Reserved` | 分享版：結構、頁碼與例題編號、依概念命題的內容（框架 v1.2 的 `concept-based`，2026-10-14 加入）、AI 補充內容、開放授權擴充內容；改編自特定例題、習題或資料的內容會移除 |

第三種的課堂合理使用（著作權法第 46 條）**不由程式判斷**，一律走分享版篩選；是否放寬，等法律意見（第 2 節第 24 條的條件不變）。

## 3. M1 工作項目

依順序實作，每項可單獨提交與測試。

### 3.1 收尾：claude.ai 測試的 9 項待決定事項

照 `docs/test-log/2026-10-11-claude-ai-run-1.md` 的建議處理（`possibleBridges` 入 schema、干擾選項過近的檢查、遊戲打亂選項順序、`report` 只放 `final`、`sim` 逐格檢查；第 4、5、8 項延後；第 9 項見 3.9）。與 D2、D3 合併為框架 v1.1。

### 3.2 完整備份（框架第 9 章第 12 條）

- 首頁「備份」：匯出所有世界紀錄與進度為單一 JSON（`expert-quest-backup/1`）；匯出前提示「含有文件內容，僅限個人使用」。
- 「還原」：預覽要加入或覆蓋的世界，確認後寫入；同 ID 的世界讓使用者選擇保留哪份。
- 首頁顯示「上次備份：N 天前」，超過 14 天提醒。

### 3.3 審閱頁（老師專用，新功能）

`#/world/<id>/review`：不經地圖，以清單呈現整個世界，讓老師在發給學生前檢查正確性（第 6 節「不得把知識講錯」）。

- 依章 → 技能群 → 技能列出技能頁與所有練習關卡：題目、正解（由 `engine/expr.js` 算出的數值）、干擾選項與其對應的錯誤、出處頁碼、`confidence`、`origin`。
- 每題可「標記有誤」並填一句說明；標記存在世界紀錄的 `reviewFlags`。
- `app/fix-request.js` 把 `reviewFlags` 併入修正請求，老師一鍵複製貼回 AI。
- 進度條：已看過／全部；沒有 `exploratory` 題與未處理標記時，顯示「可發給學生」。

### 3.4 班級版匯出（框架 7.4 分享版篩選規則）

- `engine/share.js`：純函式 `buildShareWorld(world)` → `{ world, removed: { count, byLicense }, credits, nonCommercial }`，嚴格照 7.4 移除、保留與產生出處清單；有單元測試，含三種教材來源各一份 fixture。
- 匯出畫面先顯示摘要：「將移除 N 段著作權保留內容；學生需持有原書對照頁碼」「含 NC 內容，不可商用」。
- 輸出檔為一般世界檔（`world.json`），另加 `distribution: "class"` 標記，學生端據此隱藏工作台與修正請求。

### 3.5 學生入口

- 首頁「加入班級世界」：選檔或貼上連結。連結形式 `app/#/join?url=<世界檔網址>`，網址需允許跨網域讀取（GitHub、GitHub Pages 可以；Google Drive 不行，介面說明）。
- 匯入後直接進入遊戲；學生的首頁只列世界與「繼續」，教學頁與工作台收在「我也想自己做」之下。

### 3.6 示範世界（D4）

- 放在 `examples/<world-id>/`，首頁「先玩玩看」一鍵載入；世界的 `license` 與出處清單完整，可通過 `npm run validate`。
- 生成過程寫成 `docs/test-log/` 的一次測試紀錄。

### 3.7 PWA 與部署（D5）

- `manifest.webmanifest`、圖示、service worker（預先快取 `app/`、`engine/`、KaTeX；世界資料本來就在 IndexedDB）。
- GitHub Actions：`npm test` 通過後部署到 GitHub Pages；`library/`、`worlds/` 不在部署內容中。
- 「關於」頁：原始碼連結（AGPL）、框架授權（CC BY-SA 4.0）、KaTeX 授權、參考作品的免責聲明（第 25 條）、隱私說明（資料只存在你的瀏覽器）。

### 3.8 手機測試

- 地圖觸控移動、技能頁與作答在 375px 寬度可用、KaTeX 長公式橫向捲動；結果寫入 `docs/test-log/`。

### 3.9 不在 M1

引擎 C（技能樹、成就）、D（分級測驗、間隔複習、遭遇）排在 M2（引擎 B 依 claude.ai 實測第 9 項提前到 M1，七種圖資料全部繪製）；班級進度回報（D6）、技能索引匯出、世界總覽、P7 連結排在 M2–M3；API 模式、Tauri 之後。


## 4. 完成標準

1. 一位沒看過本專案的老師，只靠公開網址與教學頁，能在一個下午內用 claude.ai 生成一章世界、審閱、匯出班級版。
2. 學生在手機上點連結，一分鐘內進入遊戲，離線後仍能繼續。
3. 班級版經 `engine/share.js` 測試證明不含任何 `LicenseRef-All-Rights-Reserved` 或 `NOASSERTION` 的內容欄位。
4. `npm test` 全數通過；部署流程在 GitHub Actions 上綠燈。

找一到兩位老師實際試用第 1 項，就是 M1 的驗收方式，結果寫入 `docs/test-log/`。
