# 遊戲畫面 A 段：核心可玩版 設計

- 日期：2026-10-09
- 狀態：已實作並合併（2026-10-10）
- 範圍：CLAUDE.md 第 7 節第 6 步（引擎升級）的第一段。原計畫在生成完成後才做，使用者要求提前，以便邊生成邊試玩。
- 框架依據：`framework/expert-quest-framework.md` v0.9（以下「框架 x.y」指其章節）

## 1. 目標與範圍

做出一個能在瀏覽器中遊玩的引擎：載入世界檔或世界片段，在寶可夢式的像素地圖上自由走動，找到街燈（技能）與委託人（練習關卡），在側邊面板閱讀技能頁、作答、取得經驗值、升級並點亮街燈。

引擎升級拆成五段，本文件只涵蓋 **A**：

| 段 | 內容 | 本文件 |
|---|---|---|
| A | 載入、地圖、移動、技能頁、五種題型、經驗值與等級、進度保存、KaTeX | 是 |
| B | 七種圖資料的繪製（框架 8.4） | 否：A 只顯示圖的文字摘要 |
| C | 技能樹畫面、道館與晉階 Boss、成就 | 否：道館先顯示「即將開放」 |
| D | 分級測驗、間隔複習、草叢遭遇、暫定點亮 | 否：草叢先只有外觀 |
| E | 貼上片段、驗證結果介面、修正請求（第 7 步的 `app/`） | 否 |

**成功標準**

1. 用 `test/fixtures/valid-world.json` 與第 1 章的真實片段都能載入並遊玩。
2. 每盞街燈、每個委託人、每座道館都走得到（由測試保證）。
3. 五種題型都能作答；數值題的答案與選項全部由 `engine/expr.js` 計算。
4. 重新整理頁面後，世界與進度都還在。
5. 手機寬度約 400px 可玩（點地面移動、底部抽屜面板）。
6. 引擎不含任何特定書籍的資訊（CLAUDE.md 第 5 節）。

## 2. 畫面

### 2.1 版面

- **地圖**全螢幕；**側邊面板**在右側，約佔 36% 寬。手機（寬度小於 720px）改為**底部抽屜**，可拉高、收起。
- 面板關閉時地圖佔滿畫面。地圖左上角是狀態列（世界名稱、已點亮數／總數、總經驗值），左下角是按鈕（帶我去、書本地圖、開啟世界）。

### 2.2 地圖美術

- 依使用者核可的示意圖 `docs/superpowers/specs/assets/map-art-v5.html`：16×16 像素圖塊，全部由程式繪製，固定配色；圓形樹冠的樹林、帶水光邊緣的水面、層狀岩壁與階梯、木板橋、沙土路、深色草叢、花。
- 不使用任何既有遊戲的圖像、角色或名稱（CLAUDE.md 第 2 節第 25 條）。
- 遊玩時鏡頭跟著角色，以整數倍放大（依視窗大小，約可見 15×10 格）；`image-rendering: pixelated`。
- 水面與亮著的街燈光暈有輕微動畫；`prefers-reduced-motion` 時停止。

### 2.3 知識與地圖的對應

| 世界中 | 地圖上 |
|---|---|
| 技能群（章） | 城鎮；依 `clusters` 的順序沿道路排列 |
| 技能群的道館（`cluster.boss`） | 城鎮最深處的道館建築（A：即將開放） |
| 核心技能（`kind: core`） | 主街北側的街燈，依先修順序由入口排到道館前 |
| 支線技能（`optional`） | 從主街分出的小巷中的街燈 |
| 應用與工具技能（`app`、`tool`） | 城鎮邊緣的街燈 |
| 委託情境練習（`context: commission`） | 街燈附近的人物，頭上有「！」直到完成 |
| 學科情境練習（`context: subject`） | 街燈旁的告示牌 |
| 城鎮之間 | 沙土道路，兩側有草叢（D 段才有遭遇） |
| 階級提高 | 岩壁與階梯；較高階級的城鎮在高台上，地面顏色不同 |
| 先修關係 | 不畫電線（像素地圖上會雜亂）；改在技能頁列出，並由「！」引導順序 |

街燈的狀態：

| 狀態 | 條件 | 外觀 |
|---|---|---|
| 已點亮 | 技能 Lv1 以上 | 燈泡亮、有光暈 |
| 可以學 | 世界內的先修都已點亮 | 燈泡暗，燈柱上有小星號 |
| 先修未滿足 | 其他 | 燈泡暗（仍可互動，不鎖） |
| 暫定點亮 | D 段使用 | 預留樣式 |

## 3. 架構

全部是瀏覽器原生 ES module，不需要打包工具；`engine/` 內的純邏輯模組也能在 Node 測試。

| 檔案 | 職責 | 依賴 | 測試 |
|---|---|---|---|
| `engine/index.html` | 外殼：畫布、面板容器、狀態列、按鈕、檔案選擇 | 其他模組 | 手動 |
| `engine/main.js` | 啟動、狀態管理、把各模組接起來 | 全部 | 手動 |
| `engine/layout.js` | 依世界產生圖塊地圖與物件位置；可走判斷；尋路 | 無 | 自動 |
| `engine/tiles.js` | 像素圖塊與物件的繪製函式（自示意圖整理） | 無 | 手動 |
| `engine/map.js` | 畫布繪製、鏡頭、格狀移動、輸入、互動 | `layout.js`、`tiles.js` | 手動 |
| `engine/questions.js` | 題目準備與判分 | `expr.js` | 自動 |
| `engine/progress.js` | 經驗值、技能等級、街燈狀態、「！」目標 | 無 | 自動 |
| `engine/panel.js` | 面板：技能頁、作答、術語下潛與返回 | `questions.js`、KaTeX | 手動 |
| `engine/store.js` | IndexedDB 保存世界與進度 | 無 | 手動 |
| `engine/vendor/katex/` | KaTeX、mhchem、字型（MIT，附授權檔） | — | — |

既有模組沿用：`engine/expr.js`（求值器）、`engine/merge.js`（片段合併）、`engine/check-world.js`（載入時檢查）。

舊的 `engine/index.html`（v0.1、寫死測試書）由新版取代；舊版保留在 git 歷史中。

### 3.1 資料流

```
選擇檔案（world.json 或多個片段）
  → merge.parseImport + merge.mergeParts → { world, complete }
  → check-world（partial = !complete）→ 錯誤與提醒數量顯示在狀態列
  → store 保存世界與原始片段
  → layout.buildMap(world) → { tiles, objects, spawn }
  → map 繪製與互動；progress 依保存的紀錄計算街燈狀態
  → 互動 → panel 顯示技能頁或題目 → questions 判分 → progress 記錄 → store 保存
```

## 4. 模組細節

### 4.1 `layout.js`：產生地圖

輸入世界，輸出 `{ width, height, tiles, objects, spawn }`。相同世界 ID 與內容一定產生相同結果（以世界 ID 為種子的亂數）。

1. **城鎮尺寸**：每個城鎮的寬度依主街上的技能數決定（每盞街燈佔 2 格，再加入口與道館）；有支線技能時加一條向南的小巷。
2. **技能順序**：同一技能群內，依世界內的先修關係做拓撲排序；沒有先後關係的，依 `num`（節次）排序。世界外的先修（`report.missingPrereqs`）不影響順序。
3. **城鎮排列**：依技能群順序由左到右排列；超過地圖寬度上限時換到下一排，並改為由右到左（蛇形），城鎮之間以道路連接。
4. **階級**：相鄰兩個城鎮的階級提高時，在兩者之間加入岩壁帶與階梯，較高階級的城鎮使用高台地面。
5. **物件**：
   - 街燈放在主街北側；委託人放在所屬街燈的南側，多個委託人橫向錯開。
   - 告示牌放在街燈旁；道館放在主街盡頭。
   - 每種物件都記錄它代表的技能 ID 或練習關卡 ID。
6. **裝飾**：外圍森林、樹叢、池塘、花，只能放在「非保留區」；城鎮、道路、物件及其周圍一格都是保留區。
7. **可走判斷**：樹、水、岩壁、建築、街燈柱、人物、告示牌不可走；其餘可走（含草叢、階梯、橋）。
8. **尋路**：在可走格上做廣度優先搜尋，供「帶我去」與點地面移動使用。物件本身不可走，目標是物件旁的可走格。

### 4.2 `questions.js`：題目

- `prepare(question, seed)`：
  - 代入 `{{變數}}`。
  - 數值題用 `expr.evaluate` 算出答案；`as: "mc"` 時把答案與每個 `mistakes` 算成選項，依 `sig` 取有效位數。
  - 選擇題與數值選擇題的選項以題目文字為種子做決定性洗牌（框架 8.5 第 9 項）。
- `grade(prepared, response)`：
  - `mc`：比對選項。
  - `numeric`：用 `expr.withinTolerance`。
  - `order`：比對順序。
  - `sim`：在玩家設定的滑桿值下計算 `pass`。
  - `method`：先記錄所選方法，再判分 `then`。
- 判分回傳 `{ correct, detail }`；`detail` 是選錯選項時的 `why`、正確答案、解說 `ex`。

### 4.3 `progress.js`：經驗值與等級（框架 3.3）

進度以**技能 ID** 為鍵（跨世界共用，框架 3.5），每個練習關卡記錄答對次數。

| 規則 | 內容 |
|---|---|
| Lv1 | 答對該技能任一練習關卡 |
| Lv2–Lv4 | 在 2 個不同的該層級練習關卡答對，且已達前一級 |
| Lv5 | 答對 1 個 Lv5 練習關卡，且已達 Lv4 |
| 等級上限 | 不超過技能的 `maxLevel` |
| 經驗值 | 第一次答對某關卡：`10 × 2^(level − 1)`；再次答對同一關卡：20%；`method` 選了非最佳方法：上述的 50% |
| 答錯 | 不得經驗值，可重試 |
| 缺少層級 | 某層級沒有任何練習關卡時，技能停在前一級，技能頁顯示「可擴充」 |

另外兩個函式：

- `lampState(skillId)`：依 2.3 的表回傳街燈狀態。
- `nextTarget(position)`：回傳「可以學」且未點亮、離玩家最近（尋路距離）的街燈。

**需要框架補充的地方**（記入測試紀錄，A 段先依上表實作）：

1. 框架 3.3 沒有說明 Lv1 是否必須答對 Lv1 層級的關卡；本設計採「任一關卡」。
2. 框架 3.3 沒有說明某層級缺少練習關卡時的處理。

### 4.4 `panel.js`：面板

- **技能頁**依框架 6.4 的順序呈現：
  1. 名稱、原文名、ID、別名、節次與頁碼
  2. 標籤
  3. 定義
  4. 圖（A 顯示文字摘要）
  5. 類比與類比的極限
  6. 由來
  7. 出處
  8. 先修與後續
  9. 練習關卡清單與完成狀態
- **術語下潛**：定義與題目中出現的 `glossary` 術語以虛線標示；點下去在面板內推入詞條頁，若詞條連到技能則推入該技能頁。面板頂端有「返回」，以堆疊保存瀏覽路徑。
- **作答**：從人物或告示牌進入時，直接打開該練習關卡；作答後顯示對錯、解說、獲得的經驗值，並提供「回到技能頁」。
- **公式**：所有文字欄位經 KaTeX auto-render 排版（`$...$`、`$$...$$`、`\ce{}`）；排版失敗時保留原文，不中斷。

### 4.5 `store.js`：保存

- IndexedDB 資料庫 `expert-quest`：
  - `worlds`：以世界 ID 為鍵，存合併後的世界、`complete` 旗標、原始片段。
  - `progress`：存一筆全域進度。
  - `meta`：存目前的世界與角色位置。
- 每次答題與每次移動停止後保存（移動以節流方式，每 2 秒最多一次）。
- 所有讀寫包在 try/catch；IndexedDB 無法使用時改用記憶體，並在狀態列提示「進度不會保存」。
- 完整備份的匯出與匯入屬於 E 段。

### 4.6 `map.js`：移動與互動

- **格狀移動**：一次走一格，格與格之間平滑補間（約 150 毫秒）。方向鍵／WASD 移動，E／空白鍵／Enter 互動。
- **點擊**：點地面以尋路走過去；點物件時，走到旁邊並自動互動。
- **互動對象**：角色面向的那一格，或周圍一格內最近的物件。
- 「！」：畫在 `nextTarget` 的街燈上方，以及未完成委託的人物頭上。
- 「帶我去」走到 `nextTarget`；「書本地圖」列出技能群，點選後瞬移到該城鎮入口。

## 5. 錯誤處理

| 情況 | 處理 |
|---|---|
| 檔案不是 JSON、不是世界或片段 | 顯示 `ImportError` 的訊息，不載入 |
| 片段屬於不同世界 | 同上 |
| check-world 有錯誤 | 仍載入可遊玩的部分；狀態列顯示「有 N 個問題」，點開列出（A 段為英文訊息，中文化屬 E 段） |
| 世界缺欄位，導致繪製或判分出錯 | 該物件或題目顯示「這題的資料有問題」，其餘照常；錯誤寫入主控台 |
| 數值題運算式無法計算 | 題目顯示「這題的資料有問題」，不給選項 |
| KaTeX 排版失敗 | 顯示原文 |

A 段不在瀏覽器中跑 JSON Schema（需要打包 ajv，屬於 E 段），所以 `check-world` 前先做最小的形狀檢查：必要清單是陣列、技能與練習關卡有 ID。

## 6. 測試

**自動測試**（`node:test`，先寫測試再實作）

- `questions.js`：
  - 代入變數
  - 數值題選項由運算式計算，且依 `sig` 取位
  - 洗牌結果決定性且與題目文字綁定
  - 五種題型的判分；`method` 的非最佳方法
- `progress.js`：
  - 每條升級規則
  - 經驗值的三種倍率
  - `maxLevel` 上限、缺少層級時停止
  - 街燈狀態
  - 「！」選擇最近可學的街燈
- `layout.js`：
  - 同一世界產生相同地圖
  - 每個物件都有一格相鄰的可走格，且從出生點都能走到
  - 技能群內的街燈順序符合先修
  - 階級提高時有岩壁與階梯
  - 保留區內沒有樹或水
  - 地圖不含世界以外的書籍資訊

**手動測試**

- 用 `node tools/serve.mjs` 開 `http://localhost:8000/engine/`，載入測試世界與第 1 章片段，走完一個城鎮、每種題型各答一次。
- 重新整理確認進度保存；桌機與手機寬度各看一次。

## 7. 授權與資料

- KaTeX（MIT）放在 `engine/vendor/katex/`，附原始授權檔。
- 引擎不讀取 `library/` 與 `worlds/`：世界一律由玩家選檔載入，伺服器繼續拒絕這兩個資料夾。
- 引擎程式碼依 AGPL-3.0；「關於」連結屬於 E 段。

## 8. 不做的事（YAGNI）

- 角色動畫的多方向走路圖：A 只有面向的四個靜態姿勢。
- 音效、存檔槽、多角色。
- 先修電線、晝夜變化。
- 地圖編輯、玩家自訂外觀。
