# 原文書生成、班級版與大型世界測試（2026-10-14）

CLAUDE.md 5.1 與 M1 設計第 4 節：用著作權保留的原文書跑一次 Claude Code 生成，量測班級版會移除多少內容，再把它放大成 20 章的世界，測試遊戲本體的效能。

## 測試材料與條件

| 項目 | 內容 |
|---|---|
| 教材 | Naghettini (ed.)《Fundamentals of Statistical Hydrology》第 2 章〈Preliminary Analysis of Hydrologic Data〉（Springer 2017，著作權保留） |
| 體例 | 使用者從整本書切出第 2 章，36 頁；書上印的頁碼為 21–56（此節錄檔的 PDF 頁碼 = 印刷頁碼 − 20；整本書的 `pageOffset` 沿用上次的 10） |
| 生成者 | Claude Code（扮演聊天型 AI），框架 v1.1 |
| 玩家設定 | 與 2026-10-11 claude.ai 實測相同：背景為地球科學，目標是成為能教水文學的老師 |
| 讀取方式 | 用 `pdftotext -layout` 抽成純文字（約 11,700 字、約 25k tokens），不讀頁面圖片 |
| 存放位置 | `library/`、`worlds/`（不提交） |

## 生成結果

| 項目 | 數量 |
|---|---|
| 片段 | 5（`head`、`ch2a`、`ch2b`、`ch2c`、`final`） |
| 技能 | 11（全部核心，初階；`math/statistics`） |
| 練習關卡 | 32（遭遇 22） |
| 分級測驗 | 4 |
| Boss | 3（道館改寫自文件；晉階與最終為 AI 補充） |
| 詞條 | 18 |

- 五個片段依序合併：**0 錯誤、0 提醒**（第一次就通過）。
- 數值全部重新設定，沒有沿用書中的流量表；章末習題只改編第 8、9 題（調和平均與幾何平均）。
- 與 claude.ai 那次（同一章，21 個技能、117 題）相比，技能切得較粗；本次的目的是測試班級版與規模，不是重做內容。

## 班級版：原文書會被移除多少

| | 完整版 | 班級版 |
|---|---|---|
| 練習關卡 | 32 | **0** |
| 分級測驗 | 4 | 4 |
| Boss | 3 | 2 |
| 技能定義 | 11 | 0（改為「內容見原書，§節次，第 x–y 頁」） |
| 詞條解釋 | 18 | 0（只剩詞條名稱與頁碼） |

**11 個技能沒有任何一題可以玩。** 學生拿到的班級版只剩技能樹結構、頁碼、4 題分級測驗和 2 座 AI 補充的 Boss，街燈一盞都點不亮。

原因是框架 7.4 把「改寫自文件」的內容一律標成文件的授權。練習關卡雖然是 AI 用自己的話、重新設定數值寫成的，但仍標為 `document`，所以全部被移除。

這代表：**用一般原文書做的世界，現在無法發給學生使用**；M1 的教師流程目前只適用於開放教材與老師自編講義。這需要使用者決定（見下方待決定事項）。

## 大型世界（20 章）

把本章複製成 20 章（220 個技能、640 題、22 座 Boss，世界檔 565 KB），在 Chromium 中量測：

| 項目 | 結果 |
|---|---|
| `checkWorld`／`buildShareWorld`／`buildMap`（Node） | 37／4／26 ms |
| 匯入工作台（含檢查） | 0.25–0.5 s |
| 遊戲載入／閒置畫面更新 | 0.3–0.4 s／60 fps |
| 審閱頁（修正前） | **6.6 s**，93,000 個 DOM 節點；每勾一個「已看過」0.5 s |
| 審閱頁（修正後） | 首次顯示 0.37 s；展開一章 0.2 s；勾選 0.09 s |
| 班級版頁 | 0.06–0.7 s |

### 發現與修正

1. **審閱頁一次畫出全部題目太慢**：改為各章預設收合（三章以內全部展開），第一次展開時才產生題目卡與排版公式；摘要列顯示「已看過 x / y」。
2. **地圖是一長排**：20 個街區排成 782 × 21 格的一列，走路很遠；「書本地圖」可以直接傳送，仍可玩。可在引擎 C 段（技能樹）一併改成多列排列。

## 整本書與 context 的觀察

- 一章約 25k tokens；658 頁的整本書約 45 萬 tokens，超過多數聊天型 AI 一次能讀的量。claude.ai 那次能接受整本上傳，平台可能做了檢索或分段處理；本次無法確認 AI 是否讀過每一頁。
- 框架的流程本來就是 P1 看全書結構、P2 一次一章，所以整本書可以「P1 給目錄（或整本），P2 每章開新對話並只上傳該章」。框架 4.5 目前只說「依章分批上傳」，沒有說明這個做法，可以寫得更明確。
